# 运营后台改造 + AI 模型市场（Ops Console Revamp）

> 按用户 9/25 调整：权限管理/用户管理/版本管理不着急（单人运营），
> 重点 = ① 知识点管理、英语单词管理独立子菜单；② AI 网关升级为**模型市场**
> （运营配置多家厂商 LLM，学生端只选厂商 + 模型名）；③ 系统设置保持（价格/引导）。

## 动机（Why）

- 知识点与英语单词共用一个面板（工具栏切换），不符合独立管理直觉
- AI 网关目前只支持**单一供应商**（app_config 的 ai_gateway_*：一个 provider/base_url/key/模型列表），
  学生端只能选模型名；运营想接入多家厂商（DeepSeek/OpenAI/Anthropic/百炼/智谱…）无法满足
- 参考 QwenPaw：多 provider 结构——每个厂商有自己的凭证与模型列表，学生端只选厂商+模型

## 目标（What）

1. 主侧栏：📚 教材数据 ▸ 知识点管理 / 英语单词管理（独立子菜单）；⚙️ 系统配置 ▸ 系统设置 / AI 模型市场
2. **AI 模型市场**：运营可配置多家 LLM 厂商（名称/协议/Base URL/API Key/模型列表/默认模型/启用/默认厂商），
   每厂商可单独测试连通
3. 学生端（Settings LLM 配置）：**厂商下拉 + 模型下拉**，保存后 AI 调用按所选厂商路由；
   **OCR 面板同样**：多模态模型选择改为厂商下拉 + 视觉模型下拉（兼容模型市场）
4. 兼容：现有 ai_gateway_* 配置作为默认厂商兜底；旧模型选择（无厂商）走默认厂商

## 范围（Scope）

- 做：前端两级导航；AI 模型市场（新表 + CRUD API + 网关多厂商 + 运营面板 + 学生端选择改造）
- 不做（非目标，延后）：权限管理、用户管理、版本管理、独立数据管理菜单；
  本次不改造空间端其他页面；不引入前端框架

## 影响（Impact）

- 前端：`frontend/site/ops.html`（侧栏导航 + 系统设置/模型市场面板）、`ops_data.js`、
  新增 `ops_ai_market.js`；`frontend/src/views/Settings.vue`（厂商+模型选择）
- 后端：新增表 `ops_ai_providers`（主库）；`services/ai_gateway.py`（多厂商路由）；
  新增 `routers/ops_ai_provider_router.py`（CRUD + test）；`routers/config.py`（/config/models 返回厂商+模型）；
  `services/llm.py`（读取用户选择的 vendor）
- 风险：网关改造影响所有 AI 调用（llm.py 已统一走 AIGatewayClient，改造收敛在网关内）；
  需保证默认厂商兜底，旧配置零影响

## 验收标准（Acceptance）

- [ ] 侧栏两级导航：教材数据▸知识点管理/英语单词管理；系统配置▸系统设置/AI 模型市场
- [ ] 模型市场可新增/编辑/启用禁用多个厂商，每个厂商配置独立凭证与模型列表（含视觉模型 vision_models）
- [ ] 每厂商连通测试可单独执行（复用真实上游调用）
- [ ] 学生端 Settings：LLM 厂商下拉 → 模型下拉联动；OCR 面板厂商下拉 → 视觉模型下拉联动；
  保存后 AI 生成/出题/批改与图片识别按所选厂商路由
- [ ] 旧配置兼容：无厂商选择时走默认厂商，默认厂商未配置时回退 ai_gateway_*（LLM 与 OCR 均兼容）
- [ ] 知识点/单词列表增删改查 + AI 导入 / 批量导入回归通过
